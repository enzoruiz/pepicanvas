## Specs

- **S1 — Propagation (deliverable).** "Propagación de correlación por HTTP, WebSocket, dominio, PostgreSQL, outbox, actor, S3 y subprocesos." Stack obligation: "cada recorrido debe propagar un identificador de correlación y contexto OpenTelemetry desde HTTP o WebSocket hacia dominio, PostgreSQL, outbox, actor del canvas, S3 y subprocesos."
- **S2 — Redacted, bounded telemetry (deliverable).** "Logs, métricas y trazas redactados con cardinalidad acotada." Stack: "Logs, métricas y trazas deben permitir relacionar aceptación, persistencia, publicación y render sin incluir secretos ni contenido privado."
- **S3 — Durable manifest (deliverable).** "Manifiesto durable por ejecución con integridad, acceso y retención."
- **S4 — Independent reading (deliverable).** "Consulta y lectura independiente que recalcula resultados."
- **S5 — CTRL-TRACE-01.** "CTRL-TRACE-01 — recorrido instrumentado de TE-015 conserva una correlación consultable desde aceptación por HTTP/WebSocket hasta dominio, PostgreSQL, outbox, actor, S3 o subproceso aplicable, con redacción verificada." Minimum evidence: "prueba de integración o recorrido instrumentado que muestre una correlación continua a través de al menos una frontera asíncrona; consulta reproducible de logs o trazas por identificador y verificación de redacción."
- **S6 — CTRL-EVID-01.** "CTRL-EVID-01 — la ejecución de TE-015 conserva un manifiesto durable con release, escenario, instante, resultado, correlación, integridad, acceso y retención; una lectura independiente recalcula o clasifica el resultado." Failure: "si falta evidencia obligatoria, el resultado es `INCONCLUSO`, nunca aprobado; si la escritura durable falla, debe señalarse la ejecución como incompleta y evitar que artefactos parciales parezcan válidos."
- **S7 — CTRL-VERS-01.** "CTRL-VERS-01 — el manifiesto de TE-015 fija release, Go, módulos, Node.js, gestor de paquetes, dependencias frontend, PostgreSQL, almacenamiento S3, ffmpeg/ffprobe, navegadores y OBS exactos; cualquier diferencia obliga a repetir la evidencia afectada."
- **S8 — CTRL-SHUTDOWN-01 (deferred).** "CTRL-SHUTDOWN-01 — Diferido a TE-016 (TE-016 depende de TE-015): el exportador expone un cierre con el contrato de `Hub.Close` y descarta de forma acotada lo que no alcance a exportar, sin bloquear el proceso."
- **S9 — Exporter failure.** "Falla después de confirmar: el producto continúa aunque falle el exportador y registra pérdida acotada." Stack: "la indisponibilidad del exportador no debe bloquear el recorrido de producto ni acumular memoria sin límite; debe descartar de forma acotada, exponer la pérdida mediante métricas y mantener logs locales correlacionados." DoD: "La caída del exportador y el cierre no bloquean ni desbordan el proceso."
- **S10 — Incomplete runs and rollback.** "Falla antes de confirmar: no se marca una ejecución como completa." "Limpieza: buffers, lotes y artefactos parciales tienen límites y estado incompleto visible." "Reversión o desactivación segura: desactivar exportación mantiene logs locales correlacionados y no convierte artefactos parciales en evidencia válida."
- **S11 — Security and isolation.** "Controles de autorización: acceso a evidencia por rol autorizado; no se persisten tokens, URLs privadas ni contenido de usuario." "Pruebas de aislamiento entre streamers: correlaciones de dos cuentas no permiten consultar datos de la otra y la redacción se verifica antes de persistir."
- **S12 — Retroactive proof (rule 8).** "Las pruebas retroactivas de CTRL-TRACE-01 y CTRL-EVID-01 cubren, o justifican como «No aplica», a cada consumidor diferido cerrado; como mínimo TE-001, TE-003, TE-005, TE-007, TE-010 y TE-011." The list is computed at close over every closed consumer with a line deferred to TE-015.
- **S13 — Verification.** "Comando o comprobación: pruebas Go de integración y proceso aprobadas para el recorrido, con PostgreSQL y MinIO reales cuando corresponda." "Resultado esperado: todos los entregables y fallos declarados se verifican de forma repetible, sin estado cruzado entre streamers."

### Non-goals (stack exclusions)

"no se exige un backend específico de telemetría, trazado exhaustivo de cada frame ni alta disponibilidad del colector." "no se define un data lake, SIEM ni retención indefinida." Process-level shutdown composition belongs to TE-016.

So TE-015 adds no module: "contexto OpenTelemetry" is implemented as W3C Trace Context (`traceparent`, the OpenTelemetry propagation format) with the standard library, and any OTLP collector can ingest the exported spans later. The trace ID is the TE-003 correlation ID (both 16 random bytes, 32 lowercase hex), so every existing `correlation_id` in logs, operation rows and outbox records already names its trace. No migration: the outbox record keeps its `correlation_id`, and the publisher resumes that trace. Inbound `traceparent` and `X-Correlation-ID` stay ignored: correlation IDs are server-issued and unguessable, so one streamer cannot join or steer another's trace. Domain packages stay free of `platform` (stack rule): async boundaries are traced by decorators at composition.

- **L4** (T1 design, parent): package `backend/internal/platform/telemetry`, stdlib only, imports only `platform/correlation` and `internal/secret`. The RED spec is `backend/internal/platform/telemetry/telemetry_test.go` (written by the parent; RED: "no non-test Go files"). API: `SpanContext{TraceID correlation.ID; SpanID SpanID}` with `Traceparent()` (`00-<trace>-<span>-01`) and strict `ParseTraceparent` (`ErrInvalidTraceparent`: version `00` only, lowercase hex, non-zero IDs, exact field count and lengths). Closed span names `SpanName` constants: `SpanHTTPRequest` "http.request", `SpanPostgres` "postgres", `SpanOutboxDeliver` "outbox.deliver", `SpanRealtimeSubmit` "realtime.submit", `SpanS3` "s3", `SpanSubprocess` "subprocess", `SpanMediaInspect` "media.inspect"; any other name is exported as "unknown". Attribute keys are a closed set (`route`, `method`, `status`, `outcome`, `operation`, `kind`); others are dropped; values pass `secret.Scrub` and are cut to `MaxAttributeBytes` (64) bytes; at most 8 attributes. `Span.End(err)` sets status "ok" or "error" and never exports error text; a second `End` is ignored; `SetAttr` after End is ignored. Context: `WithTracer(ctx, *Tracer)`, `Start(ctx, name, attrs...)` uses the context's tracer (none or nil = no export) and the context's correlation ID as trace ID, or creates one and stores it with `correlation.WithID` so logs stay correlated; the child's parent is the context's current span. `SpanContextFrom(ctx)`. `Resume(ctx, stored string)` puts a stored correlation (outbox record) into ctx, ignoring a malformed value. `Tracer`: `New(Config{Exporter, QueueSize 2048, BatchSize 256, Interval 1s, ExportTimeout 5s, Logger})` (`ErrInvalidConfig` without exporter or with negative sizes); `End` enqueues without blocking, a full queue counts `Dropped`; one worker batches by size or interval and calls `Exporter.Export(ctx, []SpanData)` with `ExportTimeout`; a failed export counts its spans as `Failed` and logs "telemetry export failed" with counts only. `Close(ctx)` follows `Hub.Close`: stops accepting (later spans count `Dropped`), drains the queue, returns nil; when ctx ends first it cancels the in-flight export (counted `Failed`), counts the rest as `Discarded`, waits for the worker to exit and returns ctx's error; idempotent. `Stats()` returns `{Exported, Dropped, Failed, Discarded uint64}`. `SpanData{TraceID, SpanID, ParentSpanID, Name string; Start, End time.Time; Status string; Attributes map[string]string}` with JSON tags (snake_case).
