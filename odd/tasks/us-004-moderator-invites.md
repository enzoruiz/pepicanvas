# US-004 create and revoke moderator invitations

Issue #14 (US-004). Branch `feat/us-004-moderator-invites`, worktree `/home/enzo/projects/pepicanvas-us-004`, base `4b173a8`.
Scope: an active owner creates single-use invitation links that expire in seven days, lists the pending ones, and revokes them; an acceptance primitive (domain and PostgreSQL only) proves the revoke-versus-accept race; a minimal owner panel in /editor.

## Specs

- **S1 — Creation and expiry.** Business rule: "Cada enlace vence exactamente siete días después de su creación, es de un solo uso y puede revocarse antes de aceptarse." Criterion: "Un propietario activo crea un enlace con vencimiento registrado a siete días."
- **S2 — Owner only.** Business rule: "Solo el propietario crea o revoca invitaciones." Criterion: "Un moderador o usuario ajeno no puede crear ni revocar invitaciones."
- **S3 — No access from the link.** Business rule: "Crear o abrir el enlace no concede acceso al canvas."
- **S4 — Revocation versus acceptance.** Criteria: "Revocar se hace efectivo en la confirmación del servidor; una aceptación confirmada después se rechaza." and "Una aceptación confirmada antes de la revocación conserva la membresía y se gestiona mediante US-006."
- **S5 — Safe, non-enumerable answers.** Criterion: "Enlaces revocados o vencidos no revelan canvas, archivos, participantes ni propietario." Access: "Los identificadores no permiten cambiar de tenant. Las respuestas para enlaces inválidos, revocados o ajenos son seguras y no enumerables."
- **S6 — Link secrecy.** Criterion: "El enlace completo no aparece en errores, encabezados Referer o URLs de terceros ni registros accesibles."
- **S7 — Concurrent revocations.** Criterion: "Dos revocaciones concurrentes dejan la invitación revocada sin efectos adicionales."
- **S8 — Definition of Done.** "Creación, vencimiento, revocación, carrera y autorización tienen pruebas." "Una inspección de registros, errores y navegación confirma ausencia del enlace completo." "Dos tenants no pueden usar ni inferir invitaciones cruzadas."
- **S9 — CTRL-IDEM-01 (owner TE-007 closed: full proof).** "reintentos de US-004 (#14) antes y después de timeout o reconexión producen un único efecto y la misma respuesta; un payload distinto con el mismo operation ID se rechaza y la retención acotada se prueba en su vencimiento."
- **S10 — CTRL-WEB-01 (early primitive, deferred to TE-014).** "pruebas de US-004 (#14) cubren CSRF válido, faltante e inválido y Origin permitido, ausente y hostil, con rechazo antes del dominio, almacenamiento o upgrade WebSocket."
- **S11 — CTRL-RATE-01 (early primitive, deferred to TE-014).** "pruebas deterministas de US-004 (#14) alcanzan el límite por cuenta, sesión, streamer o IP aplicable, observan 429 o cierre documentado, verifican recuperación e independencia entre streamers." Own part: invitation creation is limited per account in memory, with `429` and `Retry-After`.
- **S12 — CTRL-TRACE-01 (deferred to TE-015).** "recorrido instrumentado de US-004 (#14) conserva una correlación consultable desde aceptación por HTTP/WebSocket hasta dominio, PostgreSQL, outbox, actor, S3 o subproceso aplicable, con redacción verificada." Own part: the request `correlation_id` reaches the logs and each stored operation record; logs carry no token, link, email, or CSRF token.
- **S13 — CTRL-RESTORE-01 (deferred to TE-017).** "una restauración de copias reales vinculadas a US-004 (#14) en entorno aislado verifica integridad PostgreSQL/assets, reconciliación y RPO/RTO observados sin exponer secretos." Own part: invitations and their operation records live only in PostgreSQL, and only the token hash is stored.
- **S14 — User decisions (L2).** Acceptance primitive in the domain and PostgreSQL, no HTTP or UI ("Primitiva de aceptación"); the token travels in the URL fragment ("Fragmento #pci_…"); "API + UI mínima"; the link is shown only when it is created ("Solo al crearlo"); the token is generated by the client ("Token generado en el cliente").

- **L3** (design, parent): (a) New package `internal/invitation` (`access` keeps TE-001 and accounts, as `subscription` did for US-002); `docs/stack.md` structure is updated. (b) The owner is the account that owns a tenant (`tenants.owner_account_id`); every owner action reads the tenant `FOR SHARE` inside its transaction and checks TE-001 (`access.InvitationRequest`, role owner, resource invitation, action administer) before touching an invitation, so moderators, strangers, and owners of an inactive subscription get the same denial without lookups. (c) Table `invitations`: random 32-hex `invitation_id`, `tenant_id`, unique 32-byte `token_hash` (SHA-256 of the `pci_` token, format `^pci_[A-Za-z0-9_-]{43}$`), `created_by`, `created_at`, `expires_at = created_at + 7 days` (DB check), nullable `revoked_at`, `accepted_at`, `accepted_by`, never both revoked and accepted. Pending means neither and `now < expires_at`; at exactly `expires_at` it is expired. (d) `invitation_operations` retains create and revoke answers for 10 minutes by `operation_id` (16-128 `[A-Za-z0-9_-]`); the fingerprint is the SHA-256 of kind, owner, and payload (token hash or invitation ID); a different payload is `ErrOperationConflict`. A token already stored under another operation is `ErrOperationConflict` too. (e) Revoke locks the invitation `FOR UPDATE` within the owner's tenant: pending or expired → `revoked_at` set once, answer `revoked`; already revoked → `revoked` with no write; accepted → answer `accepted` and nothing changes (US-006 owns the membership). An ID that is unknown or of another tenant is `ErrNotFound`. (f) Accept (primitive) locks the invitation by token hash `FOR UPDATE` and the tenant `FOR SHARE`; unknown, revoked, accepted, expired, inactive-subscription, or already-member tokens all return the one `ErrUnavailable`; otherwise it inserts a moderator membership and sets `accepted_at`/`accepted_by` in one transaction. Revoke and accept serialize on the row lock, so the later one sees the earlier commit. (g) Routes: `POST /api/invitations` (`operation_id`, `token`) → 201 `{invitation_id, created_at, expires_at}`; `GET /api/invitations` → 200 pending list; `POST /api/invitations/{invitationID}/revoke` (`operation_id`) → 200 `{invitation_id, status}`. Session 401, Origin and CSRF 403 before the body, non-owner 403 `forbidden`, malformed 400, unknown ID 404 `not_found`, conflict 409, creation limit 429. Responses never carry the token. (h) The link is `<origin>/editor/#pci_…`: the static server has no `/editor/invite` route, and the fragment is never sent to the server or in `Referer`; US-005 reads it. (i) Migration number 00007; US-003 (#13) runs in parallel and may take it first, then renumber at merge. (j) Controls: IDEM full; WEB, RATE → TE-014, TRACE → TE-015, RESTORE → TE-017 with the own parts in S10-S13.
