# US-002 manual streamer activation with one canvas

Issue #12 (US-002). Branch `feat/us-002-manual-activation`, worktree `/home/enzo/projects/pepicanvas-us-002`, base `5756810`.
Scope: operator role and its grant command, manual activation of an account into a tenant with exactly one 1920×1080 canvas, the streamer's own-canvas read, and minimal operator and canvas UI in /editor.

## Specs

- **S1 — Activation creates one canvas.** Issue: "Activar una cuenta inactiva crea o habilita un único canvas 1920×1080." Business rules: "La activación es manual." "Un streamer activo tiene exactamente un canvas con dimensiones iniciales 1920×1080."
- **S2 — Repeated activation.** Issue: "Repetir la activación no cambia la identidad del canvas ni crea otro." Business rule: "Repetir o concurrir activaciones conserva el mismo canvas."
- **S3 — Concurrent activation.** Issue: "Dos activaciones concurrentes producen un solo canvas."
- **S4 — Operator only.** Issue: "Una persona sin rol operativo no puede activar cuentas." Access: "La autorización se reevalúa al confirmar la activación."
- **S5 — Atomic failure.** Issue: "Una falla no deja suscripción activa sin canvas ni canvas duplicado."
- **S6 — Editor and isolation.** Issue: "El streamer activo puede abrir su editor; otro streamer no puede obtener su canvas." Access: "Las pruebas con dos streamers verifican identidades de canvas distintas y ninguna lectura cruzada."
- **S7 — Definition of Done.** "Activación inicial, repetida, concurrente, fallida y no autorizada tienen pruebas." "Se demuestra un único canvas 1920×1080 por streamer activo." "El control GATE-001 incluye esta superficie."
- **S8 — CTRL-IDEM-01.** "reintentos de US-002 (#12) antes y después de timeout o reconexión producen un único efecto y la misma respuesta; un payload distinto con el mismo operation ID se rechaza y la retención acotada se prueba en su vencimiento."
- **S9 — CTRL-WEB-01 (early primitive, deferred to TE-014).** "pruebas de US-002 (#12) cubren CSRF válido, faltante e inválido y Origin permitido, ausente y hostil, con rechazo antes del dominio, almacenamiento o upgrade WebSocket."
- **S10 — CTRL-CONS-01 (deferred to TE-012).** "prueba de integración de US-002 (#12) confirma dominio y outbox en una transacción, fuerza una caída antes de publicar y verifica entrega posterior sin pérdida ni confirmación WebSocket fantasma." Own part: the activation commits tenant, membership, canvas, and operation record in one PostgreSQL transaction; TE-012 adds the outbox event to it.
- **S11 — CTRL-TRACE-01 (deferred to TE-015).** "recorrido instrumentado de US-002 (#12) conserva una correlación consultable desde aceptación por HTTP/WebSocket hasta dominio, PostgreSQL, outbox, actor, S3 o subproceso aplicable, con redacción verificada." Own part: the request `correlation_id` reaches the logs and the stored activation record; logs carry no email, token, or CSRF token.
- **S12 — CTRL-RESTORE-01 (deferred to TE-017).** "una restauración de copias reales vinculadas a US-002 (#12) en entorno aislado verifica integridad PostgreSQL/assets, reconciliación y RPO/RTO observados sin exponer secretos." Own part: operators, tenants, memberships, canvases, and activation records live only in PostgreSQL.
- **S13 — Operator grant (L2).** The operator role lives in a PostgreSQL `operators` table and is granted from the host with `server grant-operator <email>`.
- **S14 — Surfaces (L2).** Operators activate over an authenticated HTTP API and a minimal operator screen in /editor, identifying the account by email. After sign-in, the streamer's editor shows its own 1920×1080 canvas, or a safe message when the account is not active.

### Non-goals

Issue: "Facturación, planes, renovaciones y canvas adicionales." Also: deactivation (US-003), invitations and moderators (US-005), revoking operators, the general CSRF/Origin/rate-limit middleware (TE-014), the outbox (TE-012), WebSocket.

- **L3** (design, parent): (a) A streamer is a tenant owned by one account: `tenants` gains `owner_account_id` (unique) and `canvas_id`; activation creates the tenant, the owner membership, and the canvas, or sets an existing tenant back to `active`, keeping its canvas. Tenant and canvas IDs are random 32-hex. (b) The activation transaction locks the target account row (`FOR UPDATE`), so concurrent activations of one account serialize; the unique owner index is the backstop. (c) The operator fact is read inside the same transaction (`FOR SHARE`) and checked with TE-001 (`access.OperatorRequest`, role operator, action activate) right before commit; operators act platform-wide, so the request's actor tenant is the target tenant. (d) Activation is idempotent by `operation_id` (16-128 `[A-Za-z0-9_-]`) for 10 minutes: the record keeps the SHA-256 fingerprint of operator ID and normalized email, the result, and the correlation ID; a different payload under a retained ID is `conflict`. A new operation ID for an already active account returns the same tenant and canvas (natural idempotency, S2). (e) Errors: no session 401; missing or invalid CSRF 403 before the body is read; non-operator 403 `forbidden` before the target account is looked up, so non-operators cannot enumerate emails; malformed email or operation ID 400 `bad_request` (structural, reveals no account); unknown email for an operator 404 `not_found`. (f) `GET /api/canvas` returns the canvas of the tenant the account owns when its subscription is active; anything else answers the same 403 `forbidden`. (g) CTRL-CONS-01, CTRL-WEB-01, CTRL-TRACE-01, and CTRL-RESTORE-01 owners (TE-012, TE-014, TE-015, TE-017) are open, so they are deferred with the own parts in S9-S12.
