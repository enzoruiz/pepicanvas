## Design

- Authorization: usage read = canvas `view`; upload, attach, detach = canvas `edit` (owner and moderator). Every denial is the same `forbidden`. A `media.Store` decorator reauthorizes with `access.GuardMutation` before every `Apply`; `MediaStore.Apply` reads the tenant with `FOR SHARE` after the quota lock and returns `media.ErrInactive` for an inactive tenant (same pattern as `CanvasStore.Apply`). Deactivation never touches `media_usage`.
- Routes (all under `/api/tenants/{tenantID}/canvases/{canvasID}/media`): `GET usage` → `{quota_bytes, used_bytes, reserved_bytes, available_bytes}` only; `POST uploads` raw body with exact `Content-Length` as declared size, `operation_id`, `reference_id`, optional `replace`; `POST references` (attach `{operation_id, asset_id, reference_id}`); `POST references/{referenceID}/detach` (`{operation_id}`). Mutations use ingress class `Session`; upload applies a per-account limit with `Ingress.Allow` after the session and before reserve.
- Outbox: `media_usage` records in `canvas_outbox` (migration 00010, no revision), written in the media transaction whenever usage changes, carrying only the aggregate usage; the publisher delivers them to the canvas actor as a usage event.
- Server: media is optional; S3 + inspector + reconciler wired from `PEPICANVAS_S3_*` and the cgroup root env; without them the usage route works and uploads answer a closed `media_unavailable` error.
- UI: editor quota meter (decimal bytes) and an upload form that refreshes the usage.
